## The ten-second GIF (README)

Story page → the recipient-conflict row → the drawer opens on the rule → "Is R-0037 cleared for a transfer?" → the abstention lands. It is recorded from the running stack, not by hand:

```bash
pnpm --filter web record:gif
```

(`apps/web/scripts/record-gif.mjs`: Playwright frames at 1120×640, encoded in pure JS to `docs/demo.gif`, about 2 MB.) Reseed first so the exception row is there to click.

## Screens at desktop width

`node scripts/shot.mjs / /story /build admin:/today admin:/money admin:/lab` (from `apps/web`; `admin:` signs in first) writes 1366×820 PNGs to `.shots/`; `node scripts/shot-palette.mjs` captures ⌘K empty, searching and asking. Useful for a design pass without a screen recorder.

## Before you record

- `pnpm db:seed` for a clean world (`DEMO_CLOCK=2026-04-20`); the story's three exceptions are seeded with the detectors' own titles, so the page is stable from the first second. Approving the proposal changes the seeded world — reseed before recording again.
- The ids in this script are the seed's at this commit: the story mare is `R-0037`, the proposal holds `R-0050` for `E-26-0054`, the returned mare on the settlement page is `R-0052`. If the seed changes, read them off the story header and the Ask chips rather than trusting this file.
- A deployed demo is one shared world. Another reviewer can settle the sale or take QuickBooks down between your steps; `pnpm demo:reset` puts it back, and a public deployment should reset it on a schedule (see `deploy/kubernetes/README.md`).
- Run the API with Redis (`docker compose up -d redis`) so "kill the worker" pauses real queues; the lab also runs inline, with the same ledger.
- With `ANTHROPIC_API_KEY` set, ask one question first to warm the prompt cache. Without a key, a local Ollama model answers if one is running (`OLLAMA_MODEL`; the honesty page's _Model_ row says which): ask one question first so the model is loaded, and expect a small model to take a minute per answer — the panel says so. `ASK_PROVIDER=offline` gives the deterministic answerer, which is what the recorded walkthrough and the Playwright suite assume.
- With Stripe keys set, `stripe listen --forward-to 127.0.0.1:3101/integrations/stripe/webhook` and pay a hosted invoice with `4242 4242 4242 4242`; replay with `stripe events resend evt_…` — the same scoreboard, with a real event id.
